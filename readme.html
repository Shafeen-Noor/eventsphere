1. Executive overview

EventSphere turns every celebration into its own interactive website. Hosts create an event in under a minute — no app install for guests — and share a QR code or link. Guests join by name, upload photos and video, leave guestbook messages, react to media, and participate in polls, challenges, and seating lookups. Hosts run a live dashboard with moderation, analytics, and upgrade controls.

Product vision: One QR Code. Every Memory. Replace disposable cameras, scattered group chats, and ad-hoc photo sharing with a single branded hub that works in any mobile browser.

1

Create event — type, name, date, atmosphere

2

Share QR + invite link from host dashboard

3

Guests join, upload, guestbook, feed

4

Upgrade when limits are hit (Essential / Premium)

Live production URL: https://eventsphere-orcin.vercel.app — deployed from the web/ directory on Vercel with PostgreSQL (Neon) and S3 storage. See the MVP report for shipped features and user flows.

Business model is pay-per-event with optional Enterprise subscription. Recommended go-to-market pricing (used in investor materials) is Essential $19 and Premium $39 per event; the codebase currently charges $9 and $29 respectively for MVP testing. Unit economics are documented in the CAC report and LTV report.

3. Technology stack

Frontend

  • Next.js 16 — App Router, React Server Components, API routes
  • React 19 — Client components for camera capture, polls, feed
  • TypeScript 5 — Strict typing across lib and components
  • Tailwind CSS 4 — Utility styling via PostCSS

Backend & data

  • Prisma 7 — ORM with PostgreSQL adapter (@prisma/adapter-pg)
  • PostgreSQL — Neon / Supabase / Vercel Postgres in production
  • jose — Session token signing (HTTP-only cookies)
  • zod — Request validation on all API routes

Media & storage

  • AWS S3 — Presigned PUT/GET for guest uploads
  • sharp — Server-side thumbnail generation (WebP)
  • jszip — Host ZIP download of all event media
  • Local fallback — .data/uploads/ when S3 is not configured

AI & deployment

  • OpenAI API — Optional captions, recaps, event Q&A (gpt-4o-mini default)
  • Vercel — Production hosting; build runs Prisma migrate + Next build
  • GitHub Pages — Static materials hub on gh-pages branch

4. Prerequisites & local setup

Prerequisites

  • Node.js 20+ and npm (or pnpm/yarn)
  • PostgreSQL — free tier at Neon recommended; use the pooled connection string
  • AWS S3 bucket (optional for local dev — uploads fall back to disk)
  • OpenAI API key (optional — AI features use heuristic fallbacks without it)

Step-by-step local setup

  1. Clone the repository
git clone https://github.com/Shafeen-Noor/eventsphere.git
cd eventsphere/web
  1. Create environment file — copy the template and edit values:
cp .env.example .env
  1. Set DATABASE_URL in .env to your Postgres connection string (must include ?sslmode=require for Neon):
DATABASE_URL="postgresql://USER:PASSWORD@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require"
  1. Install dependencies — Prisma client is generated automatically via postinstall:
npm install
  1. Apply database migrations:
npx prisma migrate deploy
# or for development with migration creation:
npm run db:migrate
  1. Start the development server:
npm run dev
  1. Open the app at http://localhost:3000, click Create event, and walk through the wizard.
Optional — seed a demo event: run npm run db:seed-demo after migrations to populate a sample wedding with media placeholders (requires S3 or local storage configured).

5. Environment variables

All variables are read from web/.env locally and from Vercel project settings in production.

AWS_SECRET_ACCESS_KEY Optional* Secret for the IAM user above. Pair with access key ID. …
AWS_SESSION_TOKEN Optional Temporary credentials token (STS). Only needed for assumed-role / SSO sessions. …

OPENAI_API_KEY Optional Enables AI-generated photo captions, event recaps, and “Ask about this event” responses. Without it, heuristic text is returned. sk-…

NODE_ENV Auto Set by Next.js/Vercel. Controls secure cookie flag and Prisma query logging in development. production

VERCEL_PROJECT_PRODUCTION_URL Auto Production domain alias on Vercel. Second fallback for app URL resolution. eventsphere-orcin.vercel.app

6. Database & migrations

EventSphere uses PostgreSQL with Prisma. The schema lives in web/prisma/schema.prisma and covers users, sessions, events, memberships, media, guestbook, polls, challenges, seating, face collections, feed items, and more.

Common Prisma commands

# Generate Prisma client (also runs on npm install)
npx prisma generate

# Apply pending migrations (production / CI)
npx prisma migrate deploy

# Create a new migration during development
npm run db:migrate
# equivalent: npx prisma migrate dev

# Push schema without migration files (prototyping only)
npm run db:push

# Open Prisma Studio GUI
npm run db:studio

# Seed demo data
npm run db:seed-demo

Migration history

10. Storage (S3 vs local fallback)

Media upload flow is orchestrated in web/src/lib/storage.ts. The storage driver is selected automatically at runtime:

  1. If STORAGE_DRIVER=local → always use local disk
  2. If AWS_S3_BUCKET is set and credentials exist → S3 presigned URLs
  3. If bucket is set but no explicit credentials → S3 (uses instance/profile credentials)
  4. Otherwise → local disk at web/.data/uploads/

Upload flow

Guest → POST /api/events/[slug]/media/uploads
     ← { uploadUrl, headers, key, driver }

Guest → PUT uploadUrl (S3 presigned or /api/media/local-upload)

Guest → POST /api/events/[slug]/media/[mediaId]/complete
     ← thumbnail generated via sharp, feed item created

S3 object key layout

events/{eventId}/media/{mediaId}/original-{filename}
events/{eventId}/media/{mediaId}/thumb.webp

Production recommendations

  • Create a dedicated S3 bucket with CORS allowing PUT from your app domain
  • IAM policy: s3:PutObject, s3:GetObject, s3:DeleteObject, s3:HeadObject on arn:aws:s3:::bucket/events/*
  • Set lifecycle rules to expire objects after plan retention windows
  • Never commit .data/uploads/ — it is gitignored

11. Deployment on Vercel

Initial setup

  1. Push the repository to GitHub (Shafeen-Noor/eventsphere).
  2. Go to vercel.com/new and import the repository.
  3. Set Root Directory to web (critical — the Next.js app is not at repo root).
  4. Framework preset should auto-detect as Next.js.

Environment variables (Vercel dashboard → Settings → Environment Variables)

DATABASE_URL          = postgresql://…?sslmode=require
AWS_REGION            = ap-southeast-2
AWS_S3_BUCKET         = your-eventsphere-bucket
AWS_ACCESS_KEY_ID     = AKIA…
AWS_SECRET_ACCESS_KEY = …
NEXT_PUBLIC_APP_URL   = https://eventsphere-orcin.vercel.app
OPENAI_API_KEY        = sk-…   (optional)

Build configuration

The web/package.json build script handles database migrations automatically:

"build": "prisma generate && prisma migrate deploy && next build"

Post-deploy checklist

  • Assign a stable production domain alias in Vercel → Settings → Domains
  • Update NEXT_PUBLIC_APP_URL to match the production alias (not preview URLs)
  • Verify S3 CORS includes the production origin
  • Create a test event and upload a photo end-to-end
  • Confirm QR codes resolve to the production URL
Preview deployments inherit VERCEL_URL for app URL fallback, but QR codes generated during preview will point at preview URLs. Always test share links on the production deployment.

13. Known limitations

Simulated payments. Upgrade endpoints (/api/events/[slug]/upgrade and /api/account/subscribe) require confirmPayment: true in the request body but do not integrate with Stripe or any payment processor. The two-step flow (402 → confirm) is a placeholder for future billing integration.
No production face AI. The “Face grouping” feature (Premium+) supports manual collection creation and tag assignment by organizers/guests. There is no automated face detection or recognition pipeline — no AWS Rekognition, no on-device ML. Tags are user-created with optional bounding box JSON.
  • Email delivery not connected — OTP codes are shown in the API response and verify page as demo codes; no SMTP/SendGrid integration.
  • Free tier is live — contrary to early investor models that assumed paid-only GTM; Free tier (5 guests, 40 media, 24h) is active in code.
  • Single-region S3 — no CDN or multi-region replication configured by default.
  • No real-time WebSocket feed — live feed uses polling, not push subscriptions.
  • Enterprise API token — token is generated and stored hashed, but external API documentation is minimal.
  • Retention enforcement — expired events are read-only in UI; S3 lifecycle cleanup is manual.

14. Troubleshooting common issues

Build fails on Vercel with Prisma error

Symptom: prisma migrate deploy fails during build.

  • Verify DATABASE_URL is set in Vercel env vars for Production, Preview, and Development
  • Use the Neon pooled connection string (-pooler hostname)
  • Ensure the database is reachable (Neon project not suspended)

Uploads fail or images don’t appear

  • Check S3 bucket CORS policy allows PUT from your app origin
  • Verify AWS_REGION matches the bucket’s actual region
  • Confirm IAM credentials have write permissions on events/* prefix
  • For local dev without S3: omit AWS vars; files land in .data/uploads/ and serve via /api/media/file
  • Ensure NEXT_PUBLIC_APP_URL is set — local upload callbacks depend on it

QR codes / invite links point to wrong URL

  • Set NEXT_PUBLIC_APP_URL to your stable production alias
  • Do not rely on VERCEL_URL preview domains for share links
  • After changing the env var, redeploy to pick up the new value

“Sign in to continue” when upgrading

  • Event upgrades require a registered host account with verified email
  • Complete signup → verify OTP at /verify → retry upgrade

Plan limit errors (402 / PLAN_LIMIT)

  • Free tier caps: 5 guests, 40 media, 24-hour retention
  • Upgrade via host dashboard or POST /api/events/[slug]/upgrade
  • See Plans & pricing for full limits matrix

AI features return generic text

  • Set OPENAI_API_KEY in environment
  • Without the key, captions and recaps use deterministic heuristic fallbacks in web/src/lib/ai.ts

GitHub Pages 404

  • Confirm Pages source is branch gh-pages, folder / (root)
  • See docs/GITHUB-PAGES-SETUP.md for step-by-step fix
  • Wait ~1 minute after saving settings for DNS propagation

Database schema out of sync locally

# Reset and re-apply all migrations (destructive — dev only)
npx prisma migrate reset

# Or push schema directly (skips migration history)
npm run db:push
